The backend defines two recurring report tasks:

- A weekly HTML email digest.
- A monthly PDF report attached to an email.

A scheduled report attempt depends on the configured Celery Beat and workers running, plus a completed analysis and an active owner email. Source configuration does not prove those services are active for a deployment, and provider acceptance does not prove inbox delivery.

<Callout>
  The report task gives Free plans at most one available recommendation preview; paid plans pass the full recommendation set to the templates. The weekly digest displays at most three recommendations, while the monthly PDF renders the full supplied set. These plan and content rules do not guarantee that a report is sent or delivered.
</Callout>

## Weekly email digest

The weekly task renders an HTML email with:

- Total revenue.
- Average contribution margin.
- The number of menu items in the analysis.
- Up to three recommendations associated with the latest completed analysis; the task does not restrict them to recommendations created during that week. Projected monthly impact appears only when a recommendation has an estimate.
- A link back to the full dashboard.

The digest template displays up to three recommendations from the task's payload. For a Free preview, pending recommendations are preferred before other statuses, then the task sorts by whether projected impact is available, its amount, priority, and recency. If there are no recommendations, no preview appears. Paid plans pass the full set, but the weekly email still displays only three.

## Monthly PDF report

The monthly task renders a PDF and attaches it to an email. The report contains:

- An executive summary with total revenue, average contribution margin, and the number of analyzed items.
- An item breakdown with each item's name, classification, price, food cost, contribution margin, menu mix percentage, and quantity sold.
- Recommendations with their type, summary, and projected monthly impact when available.
- A locked-recommendation count and upgrade link for Free accounts.

The PDF is generated as a real PDF. If the PDF renderer is unavailable, generation fails rather than sending HTML labeled as a `.pdf` file.

**Margin-display caveat:** The report task replaces missing per-item contribution margins with zero in its quantity-weighted aggregate. Since the no-cost analysis supplies no true contribution margins, its weekly and PDF average can therefore display `$0.00`; partial-cost reports also count uncoded-item margins as zero. The PDF item table renders missing contribution margins and food costs as `$0.00` too. These are zero-filled display fallbacks, not measured zero margins or costs; see the [menu matrix guide](/menuwright/menu-matrix) for the cost-coverage limits.

## Who receives reports

The current backend task chooses the first active user with the **owner** role and sends to that email; team members do not receive a separate copy through this task. The weekly digest footer identifies owner delivery, while the PDF footer says “Generated by MenuWright • Confidential.”

The default sender address is `reports@menuwright.com` (deployment configuration may override it). The email task treats an HTTP 200 response from Resend as acceptance and records the report as sent; this does not confirm delivery to the recipient's inbox.

## Schedule and timezone behavior

In the backend schedule, Celery Beat runs both dispatchers hourly. Each checks the restaurant's configured local timezone and proceeds only in the applicable 8 AM window:

| Report        | Local dispatch check                                                                          | Duplicate protection                                                                                                     |
| ------------- | --------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| Weekly digest | The dispatcher checks the restaurant's local **8 AM** hour.                                   | An enqueue-time marker prevents duplicates; after provider acceptance, another dispatch is blocked for at least 7 days.  |
| Monthly PDF   | The dispatcher checks the restaurant's local **8 AM** hour on the **first day of the month**. | An enqueue-time marker prevents duplicates; after provider acceptance, another dispatch is blocked for at least 27 days. |

The dispatcher claims a send before enqueueing the delivery task. If the email-provider request fails, the task clears the marker so a later hourly check can retry. A report-generation failure after the claim can leave the marker in place, so it may not be retried automatically. A restaurant without a completed analysis or active owner email is skipped and remains eligible for a later attempt. Celery Beat and task code describe backend behavior; they do not verify a running scheduler or worker, an active deployment, or inbox delivery.

## Plan behavior

Delivery and recommendation access are separate concerns:

| Detail        | Free                                                           | Core                        | Pro                         |
| ------------- | -------------------------------------------------------------- | --------------------------- | --------------------------- |
| Weekly digest | Up to one available preview; other recommendations stay locked | Up to three recommendations | Up to three recommendations |
| Monthly PDF   | Up to one available preview; other recommendations stay locked | Full available set          | Full available set          |

The report payload treats any plan that is not explicitly paid as Free for recommendation locking. That keeps report content aligned with the in-app recommendation preview instead of leaking the withheld set through email.

## Delivery preferences

The backend report tasks use the restaurant's configured timezone and owner email automatically. There is no separate report-recipient or frequency selector in this flow: weekly and monthly report jobs are independent recurring tasks, and the latest completed analysis is selected for each send attempt.

To view the underlying analysis and the complete recommendation experience available on your plan, use the dashboard link in the digest or open the [Menu matrix](/menuwright/menu-matrix) page.
